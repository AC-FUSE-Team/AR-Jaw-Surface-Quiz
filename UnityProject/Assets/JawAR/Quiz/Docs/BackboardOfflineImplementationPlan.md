# Offline Learning Memory Implementation Plan

## Protected baseline

The physical-phone v25 build is the protected tracking and quiz baseline. This work does not alter
OpenCV/ArUco tracking, calibration thresholds, marker configuration, jaw transforms, camera pose
conversion, surface maps, painted ownership, grading, renderer visibility behavior, orientation, or
Android graphics/CPU/backend settings. No Android build is part of this phase.

## Authority and data flow

1. `JawQuizEngine` remains the only grading authority.
2. After it returns a correct or incorrect result, an immutable attempt event is appended to a
   JSONL file under `Application.persistentDataPath` and synchronously flushed.
3. Synchronization status is an append-only companion journal. Replaying the attempt file and the
   status journal reconstructs the queue after a restart; event UUIDs provide idempotency.
4. A deterministic local scheduler uses only saved attempts. It can reorder practice, but cannot
   alter questions, region ownership, selected regions, or correctness.
5. The Unity proxy client posts queued events without blocking the quiz. A missing laptop, Wi-Fi,
   proxy, or Backboard service leaves events queued and local feedback fully operational.
6. The laptop proxy validates and deduplicates events into SQLite. Numeric dashboard statistics
   are calculated from SQLite, never generated by an LLM.
7. In real mode only, the proxy communicates with Backboard. `BACKBOARD_API_KEY` exists only in
   the laptop process environment and is never logged or returned.

## Backboard API contract verified against current official documentation

- Base URL: `https://app.backboard.io/api`; authentication header: `X-API-Key`.
- Create assistant: `POST /assistants` with `name` and an educationally constrained
  `system_prompt`; response contains `assistant_id`.
- Send a non-streaming message: `POST /threads/messages` with `assistant_id`, optional
  `thread_id`, `content`, `stream: false`, and `memory: "Auto"`.
- A missing `thread_id` creates a thread; the response includes `thread_id`, `message_id`,
  `assistant_id`, `content`, and `status`.
- Memory modes are per-message: `Auto` saves and retrieves, `Readonly` retrieves only, and `off`
  disables memory. `memory` and `memory_pro` must not be sent together.
- Memory is stored at assistant scope and shared across all threads belonging to that assistant.
  Consequently this prototype uses one assistant per anonymized student. A distinct teacher
  assistant receives aggregated/anonymized summaries only.
- Memory management endpoints are scoped by assistant:
  `GET/POST /assistants/{assistant_id}/memories`,
  `GET/PUT/DELETE /assistants/{assistant_id}/memories/{memory_id}`, and
  `GET /assistants/memories/operations/{operation_id}` for asynchronous operation status.

No real endpoint is called until the project owner explicitly approves a bounded verification.

## Unity components

- Immutable attempt record and append-only local store with JSON and CSV export.
- Deterministic adaptive scheduler. Its documented scoring combines accuracy deficit, recent
  errors, recurring confusion pairs, hint use, slow responses, and spaced review. A recent-item
  guard prevents continuous repetition, while a small deterministic mastered-item bonus provides
  periodic review.
- Timeout-bounded proxy client and restart-safe offline queue.
- `IQuizSpeechService` with an Editor/log implementation and Android TextToSpeech-only
  implementation. It has mute, stop, queue bounds, and local fallback; it never initializes
  `SpeechRecognizer` and requires no microphone permission.
- Compact portrait additions: anonymized profile selection, local/sync/Backboard status, mute,
  and a short explanation. Existing camera, controls, diagnostics, visibility, selection, and
  grading behavior stay intact.

## Laptop proxy and dashboard

- FastAPI, SQLite, Pydantic validation, bounded HTTP timeouts/retries, idempotent event inserts,
  redacted logs, and mock operation without a Backboard key or network.
- Loopback binding is the default. LAN binding requires an explicit command plus a non-empty
  prototype bearer token. CORS origins are an explicit allow-list.
- Endpoints: health, anonymized students, attempts, hints, session summaries, calculated teacher
  views, region statistics, CSV/JSON exports, and a responsive local dashboard.
- Backboard responses are treated as untrusted text: length-limited, never interpreted as
  commands, and never allowed to alter grading or scheduling records.

## Verification and stop point

- Unity EditMode tests cover persistence, restart/truncation recovery, deduplication, offline
  state, isolation, scheduler determinism, speech fallback/mute, timeout fallback, and protected
  tracking configuration.
- Proxy tests cover schemas, mock/missing-key behavior, deduplication, timeout/retry behavior,
  student isolation, calculated statistics, export, and secret redaction.
- Demonstrate the Editor UI, mock proxy, mock responses, and teacher dashboard; capture screenshots.
- Re-hash every protected artifact and compare it with the pre-change manifest.
- Stop before any real Backboard request and before any Android build.
